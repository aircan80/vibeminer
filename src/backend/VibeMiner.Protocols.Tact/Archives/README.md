# Authenticated archive-index lookup

This original C# parser continues VibeMiner Java `ArchiveIndexParser.java` and its authored tests at project checkpoint `8f353d046d961108f7acc86bfe1381004467afd5`, under the project's GPL-3.0-or-later terms. The Java source is at `protocol-tact/src/main/java/io/vibeminer/protocol/tact/archive/ArchiveIndexParser.java`; no Java runtime or third-party parser implementation is imported.

Format research uses pinned primary references [TACTSharp IndexInstance](https://github.com/wowdev/TACTSharp/blob/67fd53ac852ca297e9bf95bb41d1a97da202eba4/TACTSharp/IndexInstance.cs) and [GroupIndex](https://github.com/wowdev/TACTSharp/blob/67fd53ac852ca297e9bf95bb41d1a97da202eba4/TACTSharp/GroupIndex.cs). Their native layout distinguishes single-archive offset width 4, group width 6 (two-byte archive ordinal followed by four-byte offset), and file-index width 0. We admit only archive-only v1, zero flags, 4 KiB pages, full 16-byte keys, four-byte size/offset and eight-byte truncated MD5 checksums. Other widths/layouts remain explicit unsupported results; a six-byte group field is never treated as a six-byte offset into one archive.

Caller acquisition supplies the final 28 bytes and observed complete index length. The parser authenticates filename identity as MD5 of those complete footer bytes, the internal footer checksum, and derived count/page/TOC geometry. CDN configuration index-size hints do not replace the observed length or authenticated geometry. Callers then fetch the bounded TOC and the one selected page; these are authenticated through the footer's TOC digest and TOC's padded-page digest. TOC boundaries are maximum keys rather than the first keys used by EN indexes. Lookup checks complete selected-page ordering, exact final maximum, positive sizes and zero padding before returning a match or absence for the selected interval.

The parser does no HTTP, Range validation, source fallback, SQL, filesystem access or scheduling. Returned bindings own their proof metadata. A match authenticates an exact encoded identity, length and offset from this index; it does not authenticate any archive response bytes, prove a whole-archive digest or verify nonselected pages. The acquisition layer must validate exact source identity, Range headers/body length and observed archive bounds, then verify the requested BLTE object's EKey/CKey and complete bytes independently.
