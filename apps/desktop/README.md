# VibeMiner Electron desktop

Electron main manages one local C# engine; the sandboxed renderer presents guided discovery, dedicated preparation, the C Build overview, horizontal build areas, the Tables definition explorer, a bounded download-object ledger and the legacy local Files catalog. Preload exposes only products, bounded discovery reads, refresh, exact workspace opening, exact-generation inventory reads, exact-ledger download-object reads, bounded provider catalogue/definition reads, exact table readiness/preparation and artifact-bound row pages, cancellation, progress and a read-only authored-test disclosure. C# owns HTTP and SQLite. No renderer/main game parsing or acquisition exists.

From the repository root, use the pinned toolchain described in [BUILDING.md](../../BUILDING.md):

```sh
npm run build --workspace @vibeminer/desktop
npm run test --workspace @vibeminer/desktop
npm run start --workspace @vibeminer/desktop
```

Build the C# host first (`npm run build:backend`). The development Electron entry is `apps/desktop/dist/main/index.cjs`, preload is `dist/preload/index.cjs`, and the Vite renderer is `dist/renderer/index.html`. `npm run dev --workspace @vibeminer/desktop` serves renderer source; a standalone browser has no engine bridge. Use the built Electron app for the runnable secure boundary.

The host is launched from `src/backend/VibeMiner.Host/bin/Debug/net10.0/VibeMiner.Host.dll` in development. Packaged builds use the self-contained `resources/engine/VibeMiner.Host` executable (`.exe` on Windows). `VIBEMINER_DOTNET` overrides the development .NET command; otherwise the repository-local SDK then system `dotnet` is used. `VIBEMINER_DATA_DIR` isolates app-owned storage; default is Electron `userData/engine-v1`. `VIBEMINER_ENGINE_PATH` is a process environment override for controlled integration tests. Authored fixtures must set `VIBEMINER_AUTHORED_FIXTURES=1` to display the visible test-data banner.

Startup reads saved history without HTTP. Deliberate product changes and Refresh start discovery; selecting a row only inspects evidence. Backend filters and cursor pages retain exact identity. Search/advertisement-region filters apply to loaded pages, clearly labelled; at most 500 builds are displayed per filtered context. More selective backend filters or a new view can be used after that display bound. Saved history is separate from Local preparation. Open uses an actual saved regional source. Size-first Home verifies configurations, then reports an independent published-download capability or its typed unavailable reason. A research file catalog is not required; a configuration-only historical profile remains insufficient.

New opening uses `home-download-v1`: C# verifies configurations, acquires the declared download manifest (and encoding metadata only when required), publishes a deduplicated full-EKey ledger and returns a dated assessment. If that capability is unavailable, Home shows Unknown with the exact reason. Legacy `home-inventory-v1` results retain their separate complete-catalog Home. Preparation shows actual stages and optional measured counters. Back detaches without cancellation, matching Open reattaches, explicit cancellation awaits target retirement, and stale results cannot navigate. Discovery stays mounted through preparation/Home, preserving loaded pages, filters, selection and focus. Successful trusted results update only that exact identity's New/local-evidence fields in the preserved list.

Size-first Home shows unique encoded objects, published download content, verified local bytes at assessment, additional encoded content required and separate retained metadata bytes. Scope is all published variants in the download manifest; decoded/installed sizes and the research catalog remain unknown/unprepared. The legacy inventory Home separately distinguishes memberships, ROOT/IN logical contents, encoded objects and shared verified bytes. Counts and arithmetic use decimal strings/BigInt. Shared bytes are a subset of verified local bytes; metadata may overlap the ledger physically and is never added into a fabricated disk-space total. Region is acquisition context; the scope is All published variants with no selected research locale/platform.

Files queries only the exact sealed product/build/source/generation, with50 memberships per page (wire maximum100), a bounded128-cursor back history and no page accumulation. It shows real ROOT FileDataIDs, actual install names, full encoded/content keys, variant flags, lengths and verified-retained facts. Details retain exact raw fields. No global search, sorting, payload acquisition or upstream availability check is implied. A stale/mismatched generation is an error, never an automatic substitution. Whole-build download and future research controls are omitted until working service paths exist.

Home and Tables share horizontal build-area navigation. Metadata and Storage utilities belong to Home; the previous global sidebar is removed. Download objects keeps its local page/assessment while visiting Tables. Explicit Home/Tables area actions focus the destination heading after commit; the local Return to build overview action restores its originating control and scroll.

Tables keeps pinned WoWDBDefs community definitions separate from admitted game data. The complete provider catalogue is paged50 at a time, with bundled definitions first. Search covers provider names, hashes, FileDataIDs and bundled column names, never game records. Exact-build candidates remain community interpretations until actual source/header admission. The inspector preserves widths, sign, arrays, noninline/ID/storage annotations, unverified names and exact declared targets. Definition relations never perform row joins, label lookup or acquisition. A64-entry definition trail restores fields/tabs and invoking relation focus; catalogue selection starts a fresh trail. Explicit Structure/Relationships preference remains local across catalogue choices.

Initial Item/ItemClass catalogue activation enters Data; other entries open Structure. Deliberate Data entry checks retained readiness, reads an existing artifact immediately, and automatically prepares missing content for the fixed research locale enUS. Rows are paged50 at a time with exact artifact/filter/cursor fences and raw uint32 ID filtering. Full and protected-section Partial admissions retain separate proof/coverage; readable projection spans never establish a verified full decoded content key. Wider physical integers for unverified field names remain explicitly raw, with the original DBD hint preserved. Typed malformed UTF-8 cells show an unavailable-text status instead of their wire placeholder; the record inspector preserves exact raw hex bytes without guessing replacement text. Artifact-wide affected-value counts include copies and stay separate from protected-section coverage. Ingress checks sorted unique string-column issues, actual malformed UTF-8 without embedded NUL, a65,535-byte aggregate evidence bound per row,256KiB JSON rows and512KiB pages.

One App/session table producer survives area changes and Choose build. At most one currently visible Data view can wait for it; leaving discards waiting demand without stopping started work. Target-specific Stop waits for the actual terminal reply. Stopped/failed intents remain latched until Retry, outside the eight-view cache;2048 remembered intents is a fail-closed session bound, with no silent eviction. Retry probes local readiness before requesting missing preparation. A compact original-context background strip keeps Stop available on Discovery, preparation and a different build, without an invented cross-build return action. Terminal Dismiss preserves latches and restores focus after commit. Matching Home retains its working View action. Progress percentages describe a measured current stage only; unknown/zero denominators never imply overall progress.

Definition metadata is attributed to WoWDBDefs contributors at revision `b9a63096cdd99b26967f17f9515377ae62cadfd7`, CC-BY-SA-4.0. The UI shows provider revision, original URLs and digests. Desktop boundary fixtures derive candidate projections offline using VibeMiner's original C# DBD reader; their synthetic build lifecycle is visibly labelled and uses authored raw rows, without downloaded game payloads.

The transport validates canonical schema projections at runtime, limits each UTF-8 frame to 1 MiB, reserves request slots for cancellation/shutdown, coalesces progress at 100 ms, rejects backward progress sequences and malformed/version-incompatible data, and rejects all pending consumers on engine failure. Download-object pages validate exact product/build/source/ledger, contiguous ordinal IDs, unique full EKeys and advancing/terminal cursors. The renderer additionally pins assessment timestamp and object count to the opened summary; mismatches preserve prior rows and offer Reopen. Download objects reads50 rows per page with bounded128-cursor history and no payload acquisition, global search or sorting. Inventory replies additionally validate exact context/generation, limits, increasing source-row IDs and cursor advancement; accounting requires verified plus remaining to equal total and shared to be within verified bytes. It never replays a failed mutation. Shutdown awaits actual exit and has a five-second forced-exit fallback.

Component and transport checks use authored fixtures from `contracts/examples/`. Real Electron qualification, screenshots, package checks and platform limitations are recorded by the coordinator. The preserved [guided reference and expert reviews](../../docs/design/README.md) define the visual and interaction baseline.
