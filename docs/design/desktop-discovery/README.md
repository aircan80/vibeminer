# Desktop discovery (proposed)

Redesign of the first screen so VibeMiner feels like a desktop app instead of a scrolling web page. It replaces the layout of [guided discovery](../build-discovery/index.html?concept=guided&state=ready&product=wow) but keeps its meaning: one list of advertised and saved builds, one selected build, one Open action, no game download from browsing. Status: approved by the owner ([D059](../../DECISIONS.md)).

Open [index.html](index.html). Query options: `state=idle|refreshing|stopping|offline|partial|filtered|opening|downloading|attention|empty`, `panel=open` (with `downloading` or `attention`), `text=200`, `chrome=0` (hides the mockup state control). All values are authored samples.

**All products ([D062](../../DECISIONS.md)).** The app now follows [all-products.html](all-products.html), approved by the owner (#10): one grid for every registered product. Query options: `state=idle|refreshing|offline|filtered|empty`, `product=<id>`, `text=200`, `chrome=0`. Where it differs from index.html, all-products.html wins; the rest of this page still applies. Its **Community** pill and "Community build history" source are a sample of a later idea with no producer, so the app leaves them out.

## Window

- **No visible menu bar.** Hide it with `setMenuBarVisibility(false)` (not auto-hide, so Alt doesn't pop it up). Keep the application menu so standard roles keep working: copy/paste/select all, zoom (Ctrl+= / Ctrl+- / Ctrl+0), close and quit, and the macOS app menu.
- **Shortcuts:** Ctrl+F focuses the build filter. F5 starts Refresh builds when no refresh is running; it never cancels one. Escape closes the activity panel.
- **Fixed window, scrolling panes.** The window never scrolls, at any size or text scale. The build list and the inspector scroll on their own.

## Layout

- **Toolbar** (about 44px): the logo (28px mark, 17px wordmark) and the activity entry when there is one. No product picker.
- **Filter row**: search, **Product** (All products or one product), All / Prepared / Current, and **Refresh builds** right-aligned in the teal accent style (mint fill, teal border and text), distinct from the solid Open build. Tab order follows that order, then the build list. Refresh checks every registered product. It becomes **Cancel refresh**, then **Stopping discovery…** (`aria-disabled`, so focus stays on it), and **Retry discovery** after a failed or partial check. Product, Prepared and Current are engine-side filters; search refines loaded builds only.
- **Build list.** One row per exact build identity across all products, ordered by product (registry order), then build number newest first. Columns: Product, Version, Build, Downloaded, In VibeMiner. Build config, CDN config, the full identity, Publication and Advertised in are in the inspector only. A **Current** build (advertised at the last check) gets a warm row tint plus a **Current** label after the version, so colour is never the only signal; selection stays mint with a teal edge. It's a listbox: one Tab stop, then Up/Down/Home/End/PageUp/PageDown move the selection. The column header stays put and rows never scroll under it. **Load more builds** sits at the end of the loaded rows.
- **Notices** go between the filters and the list: **Refresh unavailable** when every checked product failed, otherwise **Refresh incomplete**, saying per product with a problem whether its own saved observations are kept ("Earlier saved observations are kept for wow." / "wowt: no saved observations.", never "every product") and listing problems per product (products that share one problem are grouped, `wow_beta, wow_classic_era: …`) with Retry discovery; and a hidden selection ("wow 12.1.5.70448 is still selected. Clear filters to see it in the list."). Errors never live only in the status bar.
- **Inspector** has three parts. The header lines up with the bottom of the list header and names the product. Identity starts with Product (ID and label); Observation keeps Publication, Advertised in, CDN routes, Last seen and File availability. Download source, **Open build** and **Source details** are pinned at the bottom at every text size. Source details shows the selected build's product check.
- **Status bar.** One line: "Checked 13 products" or "Checked 1 of 2 products · wowt not checked" (after a refresh this session it counts only the checks that refresh completed; offline or failed checks are named as "could not be checked", never counted), "Latest check …" (completed checks only; a failed attempt is never the latest check) with " · oldest …" when products were checked at different times, refresh progress across products ("Checking 13 products · 5 of 13 done…", counts only, no percentage), and a summary of background work. It drops the secondary items when text is enlarged.
- **Empty state.** Filters are disabled and the inspector collapses until there is something to select. With nothing saved it reads "No saved builds yet". A Product filter with no saved builds names that product and whether it was checked; if its latest check failed it reads "Could not check wowf" with the typed problem, never "no advertised builds". The Current filter says a product had no current build only after a completed check. When every check failed it reads "Could not check any product".

## Activity entry

- It's visible only while there is something to show: active, paused or waiting work, or an outcome still to review (failed, stopped or canceled, until **Dismiss outcome**). With nothing to show there is no entry, no badge and no floating button.
- **Needs attention** is the amber variant for outcomes to review. The status bar echoes it while the panel is closed.
- The panel is nonmodal and comes right after the entry in Tab order. It covers the inspector column and makes the inspector inert while open. Close or Escape returns focus to the entry.
- Opening a build shows its progress in the inspector, with **View preparation** and **Cancel opening**.

## Data rules

- Regions merge into one row only when the whole versions row matches: BuildConfig, CDNConfig, ProductConfig, KeyRing and unknown columns. Two rows with the same version (the TW row in the sample) are different builds. Their regions and the inspector's full identity tell them apart. Most `wow` builds show as one row.
- **Advertised in** lists the regions with a versions row at the last check. Saved rows say "None at last check".
- **Publication** ("Current: advertised at the last completed check (<time>)" / "Not advertised at the last completed check", with " · latest check failed" when the product's latest attempt failed; in the inspector, and as the Current label, which keeps reflecting the last completed check) and **In VibeMiner** (Prepared, New to VibeMiner) are separate facts.
- **Downloaded** is the share of every file the build lists (its download manifest plus every ROOT-listed file outside it, every locale and platform variant, encoded bytes) stored on this machine, kept current by the engine as pieces arrive, on demand or through Download all, with no presence check needed ([D065](../../DECISIONS.md), [D066](../../DECISIONS.md)). It rounds down, and 100% means every object in that manifest is stored. Every listed build gets a figure. A build that was never opened shows "Not opened", not 0%. Open's metadata counts only when it is itself a build file, so a fresh open shows "<0.1%" once ROOT is read. A build opened without a measured manifest shows "Size unknown", one whose content on disk is still being counted, or whose file list is still being measured after Open, shows "Counting…", one whose file list could not be read shows its manifest figure and says why in the inspector, and one whose saved ledger could not be read shows "Unavailable". "—" means the figure has not been read yet. A pulsing dot marks a build with a running Download all.
- **Download source** offers only regions that have both a versions row and a matching cdns row (SG in the sample has none). With no recorded route it shows "No recorded source route", disables Open build and says why. It never falls back to US.
- The inspector shows Product config and Key ring. A missing column shows "Not supplied"; a present but empty one shows "(empty value)". A key ring reference doesn't mean its keys are available.
- **Not prepared**: "Opening verifies configs and measures download size." **Prepared locally**: "Local evidence recorded. Game content stays on demand."
- Product labels come from the registry in `src/backend/VibeMiner.Domain/Discovery.cs`.

## Deliberate departures from the old references

- Type scale is 11 / 13 / 14 / 19px, with a 14px base instead of 15px, for desktop density.
- Muted text is `#586a64`, at least 4.7:1 on every surface here including the status bar and mint, instead of `#697b76`, which was below AA.
- Pills share one outlined style. **Prepared** is outlined so it doesn't look like the Open build button.
- Inspector is about 370px (`26.5rem`), capped at 44% of the window, so 32-character hashes fit on one line.
- The inspector's Download section shows "Downloaded: <stored bytes> of <manifest bytes> · <percent>", then Objects, Scope, Checked, Source, and Missing, Corrupt and Activity when they apply, instead of the mockup's "Downloaded: 37% of every variant" and "Updated: As pieces download". Exact bytes and objects let a user see how much is left at 99%, which never rounds up. Checked and Missing/Corrupt tell the running figure apart from the last dated presence check that corrected it. Source names every region that shares the one figure. "Every variant" became Scope ("Every file the build lists, every locale and platform"), and Not resolvable names the listed files with no encoding entry, which cannot be downloaded and are not counted, and "As pieces download" is the figure's normal behaviour, so it needs no row.
- At enlarged text, the list drops the Build column, and the inspector moves below the list as a second pane. Unlike the mockup, the inspector header keeps its product line there, so same-version builds of different products stay distinguishable.
- Once approved, this supersedes the literal-copy rule (D021) for this screen.
