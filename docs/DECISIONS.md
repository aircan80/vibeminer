## Working implementation defaults

Implementation clarification for D055: use empty public geometry Sources on failed preparation unless a complete pair passed the coherent final fence. Preserve truthful dependency/stage problems and current C2 metadata. Capped metadata records may use finite≤256KiB CPU serialization/comparison units with a scheduling turn afterward; effects may synchronously snapshot an immutable≤128KiB bridge binding before their first await. Neither exception permits I/O, whole-workflow CPU ownership or a claim that all parsing is cooperative. The desktop16MiB envelope counts reachable application buffers, explicit graphics reservations and active responses; driver/RSS/GC retention is measured separately and cannot be acknowledged as reclaimed by JavaScript disposal.

No third-party game parser is approved by a frontend, SQLite, or general-purpose library choice. Standard platform HTTP, compression, hashing, stream, and JSON APIs are permitted. Schema definition data is a separate future decision; we will write the interpreter ourselves and preserve provider attribution if such data is introduced.

## Performance rationale

C# was selected by the owner after comparing Node and modern .NET. A C# engine suits binary processing, bounded parallel work, and adapting the Java implementation. Expected performance is not a measured speedup. Compare representative inventories, table decoding, database publication, and model preparation before setting budgets or making performance claims.
