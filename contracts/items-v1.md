# Exact-build Items v1

`items-v1` uses the selected build/region and explicit enUS research locale. Parameters are flat `productId`, `buildIdentity`, `sourceRegion`, `researchLocale`; responses carry the same exact `context` object. No raw URL, SQL or path is accepted.

- `items.data` returns local `ItemsReadiness`: a current snapshot or null, plus the two actual prerequisite states. It never starts acquisition. Current source/definition/reader eligibility is checked without rehashing full row artifacts on each query.
- `items.prepare` prepares missing Item and ItemSparse through the same shared TableDataService, then validates and publishes one compact immutable Items projection. It emits ordinary bounded current-stage progress and honors independent consumer cancellation. Existing table work is awaited rather than bypassed. Navigation and Stop remain different actions.
- `items.page` adds `artifactId`, optional literal `query` (default empty), optional `exactItemId`, `limit`1..50 and opaque `after`. Empty query browses. Nonempty name query and exact ID are mutually exclusive. Results are ascending unsigned Item ID, at most50 summaries, with a next cursor when another match exists; there is no fabricated count-all result.
- `items.inspect` adds `artifactId` and canonical uint32-string `itemId`. It returns the summary and complete admitted Item/Sparse row evidence, or `detail:null` when the ID is outside this admitted Item scope. Missing Sparse differs from an absent Item. Exceptional oversized detail fails explicitly instead of truncating evidence.

Snapshots bind both original table artifacts, their source/layout/definition/provider/reader/locale evidence and feature/search revisions. Counts partition the actual Item-anchored left join; copy rows join by their emitted target IDs. Sparse-only IDs are counted separately. Replacing a prerequisite or interpretation invalidates current readiness and old query capabilities; stale artifacts/cursors are explicit failures. Held original row leases support repeat detail without full rehash per click.

Names come only from `Display_lang`. Wire states are `valid` (nonempty exact source value), `empty` (exact empty string), `invalid` (null with source text issue), and `missingSparse` (null after both admitted scopes are known). Whitespace is preserved; an invalid Description does not invalidate Display. IDs remain their own column; no invented item name is supplied.

Search is `ordinal-ignorecase-contains-v1`: literal contiguous substring using .NET ordinal ignore-case, with no normalization, wildcard or regex semantics. Input is bounded to128 Unicode scalars/512 strict UTF-8 bytes; malformed Unicode and NUL fail. Name searches exclude empty/invalid/missing names; Browse and exact IDs retain them. Cursors bind exact context, both sources, feature/query policies, query/mode, ordering and limit. Changing any input resets the cursor.

Summary `baseValues` contains at most8 separately attributed verified source fields. Property groups contain actual source column references; inspect retains every supported source field and array element. Unknown/raw physical fields keep their research labels and never become gameplay filters. Aligned stat percentages/modifiers, masks and sockets are source inputs, not calculated bonuses, final armor, damage or DPS. Independent conflicting source values stay separately attributed.

Complete page/detail response budgets are512KiB including a conservative protocol envelope/enum reserve. Exact integers remain strings. Optional icon FDIDs are source facts; image resolution/acquisition and opaque image delivery are separate bounded capabilities. The Items list remains useful when an optional image is missing, ambiguous, protected, unsupported or corrupt.

Known snapshot feature revisions are `items-projection-v1` and `items-projection-v2`; unknown revisions fail ingress. Historical v1 descriptors remain readable for source-preserving refresh, while current readiness requires v2. Revision v2 corrects the exact pinned Sparse field names `Socket_match_enchantment_ID` and `Gem_properties` in the sockets/stat-input group. It preserves original rows and does not add calculated semantics. New artifacts/cursors bind their actual revision; refreshing leaves historical CAS bytes intact.
