# Item icons v1

Capability `item-icons-v1` adds optional exact-build icon preparation and a main-process-only verified image read capability. Icons never gate useful Items rows or detail. All acquisition, source resolution, BLTE/BLP decoding, PNG publication and ready admission remain in C#.

- `items.icons` accepts flat Items context (`productId`, `buildIdentity`, `sourceRegion`, `researchLocale`), `artifactId` and1..50 ordered canonical uint32-string `itemIds`. IDs must be admitted by that exact current Items feature. Input order and duplicates are preserved in the result. No arbitrary FileDataID, URL, hash or path is accepted. Four distinct shared batches and eight total consumers bound preparation; one worker serializes source resolution and PNG derivation. Ordinary request progress reports a real current stage and known object denominators. Cancellation detaches that consumer and the last awaits actual cleanup.
- `items.icon.open` accepts the same flat context/artifact plus `itemId` and `imageArtifactId`. It reauthorizes the current exact feature/source association and opens a fully verified PNG read lease. Result `ItemIconLeaseDescriptor` contains only opaque `leaseId`, exact image `artifactId`, canonical SHA256, decimal-string `byteLength`, width and height. It contains no filesystem path. Four admissions include opening, open and draining; capacity is immediate/retryable. A monotonic30-second lifetime expires abandoned leases. This method is for Electron main's image handler; renderer/preload do not expose it.
- `items.icon.close` takes only `leaseId` and returns `{closed:true}` after actual retirement. Unknown valid handles are idempotent. Main closes after it has copied and verified a bounded immutable PNG snapshot; shutdown also drains abandoned opens/leases.

Batch outcomes distinguish ready, missing Item in admitted scope, unavailable icon field, explicit zero/no icon, missing ROOT membership, ambiguous published variants, unresolved encoding, protected, unsupported, unavailable and corrupt. Ready has a nonzero source-derived FDID and exact image descriptor; every other state has null image. No guessed icon is substituted. Complete ROOT/EN and full BLTE/CKey proof are required; a partial table source cannot stand in for a full icon source. Saved source associations preserve original configuration and metadata provenance, source selection policy, revisions and exact build admission.

Images use original BLP2 decoding and proof-carrying PNG: top-left straight RGBA, no rescaling or color conversion. Initial maximum dimensions1024, one million pixels, encoded PNG5MiB; these are limits, not every icon's actual size. Electron main serves only SHA-verified immutable response snapshots through opaque custom-protocol URLs. At most four5MiB encoded snapshots are retained through body completion; decoded browser/GPU memory is additional and requires visible-only image mounting and measurement. No JSON pixel/base64 payload or persistent second image cache is used.
