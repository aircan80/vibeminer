# Selected Item effects v1

These additive methods use protocolVersion1 and the existing success/error/progress envelopes. Program composes the effects adapter, so the Host advertises `item-effects-links-v1`, `item-effects-inputs-v1` and `item-effect-spell-names-v1` together. A Host built without an ItemEffectsService advertises none of the three and returns ITEM_EFFECTS_UNAVAILABLE for recognized, well-shaped calls. Desktop requires all three plus items-v1.

All requests have flat `productId`, `buildIdentity`, `sourceRegion`, `researchLocale: "enUS"`, `itemsArtifactId`, `itemId`. Context identity and artifact hashes are exact; itemId is a canonical uint32 decimal **string**, including zero. Replies retain nested `selection: {context, itemsArtifactId, itemId}`. No caller target ID, table, FDID, URL, local path or row evidence authorizes a join.

Each edge key is exactly `{indexOrdinal: "0"}` with canonical0–65535. Details has1–16 unique keys, Names1–8. Distinct keys can reference the same Effect and Spell; replies preserve request count/order without collapsing those occurrences. Names policy defaults only when omitted to `spell-name-by-emitted-id-v1`; explicit null/unknown is invalid. Unknown/null/duplicate properties and out-of-range primitives are rejected before adapter work. The exact canonical base64url cursor binds selection, index, index revision, order policy and page limit by SHA256; it cannot be reused for another request. Page never drops/skips an occurrence to fit bytes.

The index revision is `item-effect-bridge-index-v1`; order policy is `signed-item-unsigned-bridge-source-ordinal-v1`. Original bridge source ordinal, emitted row ID and index ordinal are separate fields. Source navigation reads the exact original Table artifact with after=sourceOrdinal,limit1 and no recordId, then verifies emitted ID/copy/parent/effect values. Target navigation uses the exact target artifact and emitted unique row ID.

Source roles are Bridge00cb674f/FDID3177687, Effect4002a5b1/FDID969941 and Name46c66698/FDID1990283. Ready sources retain complete original table snapshots, source receipts, association memberships, projection and coverage. Pinned layouts, decoder and column tuples are enforced by the canonical schema and shared relational validators. The definition and provider are the bundled pins, or with `fetchedDefinition` (D101) a WoWDBDefs definition with its own sha and commit, never the bundled commit. Only receipt `verifiedAt` observations may differ when combining already admitted snapshots; all original retrievedAt/URL/key/SHA/length/location/association/order evidence and current source preparedAt remain exact. A historical ID belongs only to NotPrepared and never supplies a Ready snapshot. Source-only unsupported readiness is possible without an index.

Two link profiles (#86, [D104](../docs/DECISIONS.md)), chosen per exact build. The bundled ItemEffect definition decides first: when every ItemEffect block the build selects stores `ParentItemID` as a relation, the build links through ItemEffect.ParentItemID; when none does, through ItemXItemEffect as above (Retail). A listed build selects its listed blocks; an unlisted one its layout candidates on the version line. Only when those disagree (1.x: Classic layouts and Classic Beta 1.60's `4CA77678`) does the definition Tables chooses for the admitted ItemEffect rows (D101, bundled or fetched) decide, by that file's layout. Readiness `link` names the chosen link (`itemXItemEffect` or `parentItemId`) whenever a Bridge source is reported, snapshot or not, so every state can name its link table; it is null with no source (MissingItem, ItemKeyOutOfRange) and while the link is still undecided. Until that file is admitted the link reads as ParentItemID, so link preparation prepares ItemEffect first and continues with ItemXItemEffect when its layout has no ParentItemID. ParentItemID links read ItemEffect FDID969941 layout `1BF9CF3A` (5.5.4, 1.15.9, 2.5.5–2.5.6, 3.80.2) for both the Bridge and the Effect role: one admission, one preparation, decoder revision v4 exactly when read with the bundled definition and v3 exactly with a fetched one (no reviewed raw rule matches its columns); the other pairings are invalid. A layout no candidate knows on an undecided line links through ItemEffect and reads as unsupported. Its eleven columns are the ten Retail ones at their declared widths, with declared references SpellCategory, Spell, ChrSpecialization, PlayerCondition, then `ParentItemID` (column 10, reference Item.ID); no column has a raw-width interpretation. Index fields are `rowId` and `itemEffectId` = (4002a5b1, 0) and `itemId` = (4002a5b1, 10): the ItemEffect row is its own effect, so an edge's `itemEffectId.value` equals its bridge `rowId`. Bridge references keep their source ordinal on either table; target references never carry one. Classic inputs are `strictNumeric` (Charges signed16, SpellCategoryID and ChrSpecializationID u16) and keep SpellCategory/ChrSpecialization as inert hints; PlayerConditionID stays `unverifiedCandidate`. Other ParentItemID layouts (`EB717848` for 5.5.0–5.5.3) read as unsupported. Examples: `item-effects-parent-*.json`, `item-effect-parent-*.json`.

Readiness distinguishes MissingItem, unsigned ItemKeyOutOfRange, NotPrepared, Ready and typed source failures. MissingItem is not admitted. Ready has an index and a ready Bridge source. Zero observed associations is a valid empty page, scoped to its admitted source.

`notInBuild` (#85) is a source state, not a failure: the exact build's ROOT lists no enUS file for that role's FileDataID (`CONTENT_VARIANT_MISSING`), so the build doesn't ship the table. Classic Era 1.15.9 has no ItemXItemEffect. Its fixed problem is `ITEM_EFFECTS_SOURCE_NOT_IN_BUILD`, "This build does not include the selected source.", never retryable. It stays separate from `unavailable` (a retryable route, timeout or local-object miss) and from `unsupported` (the file exists but no pinned layout or profile reads it, including `SCHEMA_BUILD_NOT_LISTED`). Readiness, Effect and Name outcomes carry the same state and problem as their source; like `unsupported`, a not-in-build Effect source never leads to a Name probe.

Details policy `item-effect-inputs-v1` returns exactly nine qualified fields for ObservedReady. LegacySlotIndex/TriggerType are u8; ordinary qualified numbers are signed32. Charges/SpellCategoryID/ChrSpecializationID preserve physical u32 evidence plus candidate16 interpretation; candidate references are inert hints. PlayerConditionID remains UnverifiedCandidate. SpellID keeps its original Spell.ID reference; the explicit names policy associates emitted SpellName IDs separately. Negative Effect/Spell keys never wrap; zero is an actual lookup. Missing, ambiguous, out-of-range, field-unavailable and per-source failure states carry their specific evidence/nullability.

Names preserves exact valid text (1–4096 UTF16 units, including whitespace), empty text, invalid encoding locator or textTooLarge unit count4097–65536. An invalid encoding locator requires the original Name snapshot to declare positive textIssueCount; zero or an omitted count cannot support that observed issue. No replacement label is synthesized. Missing labels distinguish complete-source absence from unknown outside readable partial scope. A final failed Effect fence clears dependent name facts; independently consulted Name source metadata can remain for late Stale/Corrupt/ResourceLimit/**Unavailable**. An initial unavailable Effect does not justify a Name probe. Shared validators match edge/effect IDs and compact Spell evidence against supplied current page/details authority before renderer combines phases.

Each accepted call owns one actual App lease across all seven operations: max4 publishers and max2 long prepares. Admission is immediate retryable ITEM_EFFECTS_BUSY; no extra Host publication pool or waiting queue exists. The lease survives service completion, success/error/cancel/oversize encoding and actual terminal newline/Flush, then retires. One encoder writes lazily into a524287-byte fixed sink: **whole envelope including escaped request ID and newline≤524288 bytes**. Oversize returns ITEM_EFFECTS_RESULT_LIMIT before partial stdout; no truncation. Refusal frames use bounded Host dispatch capacity. Cleanup failure is observed once without a second terminal; uncertain App capacity remains charged and shutdown reports ITEM_EFFECTS_CLEANUP_FAILED. Host closes the service concurrently with publisher cancellation/drain to avoid circular disposal waits.

Prepare progress is request-correlated, monotonic and source-stage truthful. Global EngineProgress gains optional nullable8hex tableId, preserving old messages. Effects-specific progress requires tableId null or one of the three consulted roles; stage≤128/unit≤32 nonempty control-free text, counters and sequence≤9007199254740991 safe JS integers, completed≤total when known. Null/zero totals stay indeterminate. Main coalesces bounded updates, rejects foreign region/role/unsafe counters, and ignores retired updates. Prepare deadlines remain21min, local reads180s; transport timeout does not refund uncertain backend resources. Cancellation acknowledgement is separate from the terminal; peers remain independent. Shutdown awaits actual producers, observers, terminal writes and lease retirement.
