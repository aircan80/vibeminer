# Creature browser v1

`creatures-v1` is advertised only when the real Creature service is supplied. C1 browses admitted client Creature records, including copy targets. This scope does not establish server spawns, locations, loot, vendors or a complete NPC population. No optional display/model preparation or model capability is exposed.

All operations take flat `productId`, exact `buildIdentity`, `sourceRegion` and explicit `researchLocale: enUS`. No arbitrary table, display ID, FileDataID, URL or path is accepted.

- `creatures.data` returns local readiness, dependency state and source artifact identity. It never starts acquisition.
- `creatures.prepare` prepares only the Creature prerequisite through the same shared Tables producer and builds the core projection. Ordinary request-correlated `EngineProgress` reports increasing sequence, actual stage/unit and trustworthy counters; unknown denominators remain null.
- `creatures.page` adds current `artifactId`, optional literal `query` (default empty), optional distinct `exactCreatureId`, `limit` (1–50, default 50) and opaque `after`. Name queries and exact-ID mode are mutually exclusive. IDs and counts remain canonical decimal strings; unsigned ID bounds include zero and 4294967295. Browse includes empty/invalid names; name search uses only valid primary Name_lang with the exact `primary-name-ordinal-ignorecase-contains-v1` policy. Query input is at most 128 Unicode scalars/512 strict UTF-8 bytes, without NUL or malformed surrogates. Cursor identity binds exact core/query/limit; byte-limited pages never skip unreturned matches.
- `creatures.inspect` adds current `artifactId` and canonical `creatureId`. It returns found detail or explicit `notFoundInAdmittedScope` with original coverage and null detail. An excluded/protected source scope never becomes global absence.

Snapshots pin `creatures-core-v1`, `primary-name-ordinal-ignorecase-contains-v1` and `creatures-direct-display-v1`, original Creature source/coverage/receipts, preparation time, exact field map and measured counts. The finite initial source is table `c9d6b6b3`, FDID 841631, layout `6E14C900`. Runtime validates original context, source admission, selected schema/provider/decoder and integrity. Optional CDI/CMD sources do not participate in core readiness, artifact identity or final core fence.

Names are valid original nonempty text, exact empty string or invalid with null value and a bounded typed table/artifact/row/column issue locator. There is no alternate-name/title fallback or replacement text. Complete raw text issues remain in original inspect/source evidence. Every summary contains four numeric source facts and four ordered slots, each retaining paired field references, the original signed DisplayID and finite float32 probability string. Positive IDs are declared, zero is noDeclaredDisplay and negative values are invalidDisplayReference. Duplicate positive declarations, zero/negative probability and all four ordinals remain visible; no random choice, probability normalization or invented gameplay label is supplied.

Counts partition admitted names and all four slots per emitted row. Inspect retains original row/copy/text evidence and source locator. Stale current Creature authority rejects core results; replacing optional targets cannot stale this core browser. Historical immutable bytes remain evidence rather than current authority. The authored [snapshot example](examples/creatures-snapshot.json) is a synthetic protocol fixture, not game-data qualification.

Host takes one of **four end-to-end result credits** after shape validation and before application work, retaining it through actual terminal encoding/stdout flush or failure cleanup. Long prepares first require one of **two immediate preparation credits** and then one of the four result credits. A third long prepare receives retryable `CREATURES_BUSY` immediately; a full result pool receives retryable `CREATURES_QUERY_BUSY`. These calls do not wait in a Host admission queue or consume every general request slot. The application's separate 32 preparation subscriptions/four query limits do not release Host publication ownership early. Two shared prepare consumers still cancel independently; the last cancellation and shutdown await actual producer/observer cleanup and terminal writes. Navigation alone does not cancel a started application-owned consumer.

Complete success and failure envelopes, including escaped request ID, every source proof/row/name/slot, protocol fields and newline, are at most **512 KiB**. One bounded encoder streams into a fixed-size sink; publication starts only after full encoding succeeds. Oversize produces typed `CREATURES_RESULT_LIMIT` with no partial frame, truncated text or dropped field. Store limits such as `CREATURES_PAGE_LIMIT`/`CREATURES_DETAIL_LIMIT` remain distinct. Four returned DTO reservations include serialization overlap; blocked stdout retains credits instead of accumulating unbounded completed results. Primitive schema limits supplement runtime cross-field/source/count/cursor/finite-float validation; they do not establish source admission.
