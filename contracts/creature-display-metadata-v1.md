# Selected Creature display metadata v1

`creature-display-metadata-v1` is advertised only with both actual C1 Creature and C2 metadata services supplied. It resolves an explicitly selected original Creature slot through CreatureDisplayInfo and CreatureModelData. The result is metadata: `appearance` is always `notEvaluated`. This capability does not acquire a model, texture or asset session and does not establish renderability, server spawns or a complete NPC population.

`creatures.display.read` and `creatures.display.prepare` accept exactly flat `productId`, exact `buildIdentity`, `sourceRegion`, explicit `researchLocale: enUS`, current C1 `artifactId`, canonical unsigned-decimal `creatureId` and integer `slot` 0–3. They reject unknown parameters. Display/model/FileDataID, arbitrary table, URL, path and caller-supplied rows are not authority. Read is local and starts no acquisition; prepare obtains only needed table prerequisites through the shared Tables producer. Prepare uses ordinary request-correlated progress with actual stage/unit/counters and monotonic sequence. Unknown denominators remain null. Cancel stops this consumer; cleanup and shutdown await the actual producer, observer and terminal write retirement.

The result echoes the exact C1 context/artifact/selection and policy `creature-display-metadata-v1`, opening proof, original Creature row locator and original coverage. Selected retains its original signed display ID, probability and paired field locators. An absent Creature has null selected; zero and negative declarations remain separate early-stop states. Duplicate slot IDs and zero/negative probabilities do not select a substitute slot.

`sources` contains zero to two actual target proofs in Display-then-Model order, without duplicate roles. Display fixes table `bfdaf9f1`/FDID 1108759; Model fixes `7f695fa5`/FDID 1365368. Each retains the original TableData snapshot, receipt, association, schema and independent partial/complete coverage. Match counts are decimal strings. Eligible exactly-one matches retain only their original emitted/copy target locator, immediate copy-source ID and strict selected ModelID/FileDataID edge. There are no complete target rows or replacement values. C2 target reference/value types are distinct from C1 references, which remain restricted to Creature table `c9d6b6b3`.

`metadataResolved` requires both unique positive edges and positive ModelID/FileDataID strings; every other state has null modelFileDataId. `notPrepared` names the next required target table. Missing and ambiguous targets stop the chain; missing conclusions use the missing source's own coverage (`absentFromCompleteSource` or `unknownOutsideReadableScope`). Zero ModelID and zero FileDataID are distinct declarations. Protected, unsupported, unavailable, corrupt and resourceLimit preserve typed bounded problems and any already admitted proofs. A positive ModelID survives a later target failure. The authored [example](examples/creature-display-metadata.json) establishes wire shape only.

Runtime validates exact snapshot/artifact/row/column equality, selected semantic widths, source receipts, role order and state consistency. Schema primitive and conditional constraints supplement those checks. Replacing Creature authority produces `CREATURES_STALE`; replacing an admitted optional target produces `CREATURE_DISPLAY_STALE` without invalidating C1 browsing. Cancellation is a request error rather than a metadata state.

C1 and C2 share the same Host two immediate preparation credits, four end-to-end publication credits and one bounded encoder. Prepare attempts a preparation credit first; a third long call gets retryable `CREATURES_BUSY`. Full publication gets retryable `CREATURES_QUERY_BUSY`. Credits are acquired after shape/service validation and before application work, retained through actual terminal stdout flush or failure cleanup. There is no Host admission queue and no separate C2 result pool. Two blocked core/metadata prepares leave capacity for core queries and local metadata reads. Internal application consumer/read budgets remain separately bounded.

Complete success/error frames including actual escaped request ID, source proofs, protocol envelope and newline are at most 512 KiB. Lazy projection and a fixed 524287-byte sink encode the whole frame before publication; oversize returns `CREATURES_RESULT_LIMIT` without partial stdout, truncation or dropped proof. One encoder remains held through actual flush. Blocked output retains the four shared publication credits, including returned results and draining terminals.
