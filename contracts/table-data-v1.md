# On-demand table data v1

Capability `tables-data-v1` adds three bounded methods. Definition browsing remains local and never triggers acquisition. `tables.prepare` acquires dependencies. The renderer automatically requests preparation when the user enters a data view that lacks admitted rows; browsing definitions remains local. All requests require exact `productId`, `buildIdentity`, `sourceRegion`, provider `tableId` and `researchLocale`; this slice supports explicit `enUS`, independent of acquisition region.

- `tables.data` returns `{snapshot:null}` for unprepared data or a verified retained `TableDataSnapshot`. No HTTP occurs. Unsupported/unbundled definitions remain typed failures.
- `tables.prepare` returns `TableDataSnapshot` after selected FileDataID resolution, source verification, complete supported parsing and durable admission. It emits bounded ordinary progress, accepts `request.cancel` and shares one producer for identical consumers. A different busy table produces `Waiting for shared table preparation`; the request observes actual retirement, then attempts its own preparation. Waiting is not a consumer of the active table: canceling the wait leaves that table running, and its failure does not become the waiting table's outcome. At most eight ownership attempts are made before retryable `TABLE_DATA_BUSY`; waiting requests remain within the existing bounded Host request admission. A canceled last active consumer waits for cleanup. Navigation can detach presentation without canceling the request; stale results never change the active selection.
- `tables.rows` additionally requires exact `artifactId`; optional `limit` is1..50 (default50), `after` is a canonical nonnegative decimal ordinal and `recordId` an optional canonical uint32 decimal filter. The cursor applies to that exact artifact/filter; changing either resets it. Pages may contain fewer than the requested limit to respect the512KiB row budget. Rows and cells remain strings, including uint32 IDs and exact integer values; no JavaScript floating-point conversion is required.

Snapshots preserve encoded full CK/EK/localSHA, source lengths, original source URL/time and authenticated loose/archive location. Separate exact ROOT membership evidence retains all eligible variant flags/ordinals and original verified EN/ROOT receipts. The enUS policy accepts all locale-bit2 memberships only when their CKeys agree; it does not invent a Windows filter. Archive locators use authenticated footer/TOC/page proofs and strict HTTP Range geometry, rather than a global research SQL index.

The actual WDC5 header must match the exact table, pinned build/layout definition and reader revision. Immutable indexed row artifacts are keyed by source/decoded hashes, schema, provider, locale and reader revision. SQLite stores small mutable registrations and exact context admissions, never the whole cell matrix.

Coverage distinguishes header-declared physical/copy counts, emitted physical/copy rows and excluded physical/copy counts. `unencryptedSections` explicitly excludes keyed sections under policy; a key declaration alone does not prove decryption was attempted or failed. Partial rows establish neither global absence nor global unique relationship targets. `excludedDeclaredRecords` is the aggregate excluded physical+copy count, not a quantity to subtract from the physical-only `declaredRecords`. Unsupported features in chosen sections fail rather than invent values. Authenticated outer BLTE clear chunks can provide a guarded partial source under `content-blte-projection-v1`: complete encoded/header/chunk proof, per-readable-range SHA-256 and unavailable spans with declared geometry/key names. Reads touching holes fail. Required WDC5 metadata and admitted dependencies must be readable; each unavailable span must belong wholly to an excluded protected section. This does not verify the full decoded CKey. Unsupported encrypted framing or unavailable required metadata fails explicitly.

Optional column `interpretation` records `raw-physical-integer-v1`, physical width/sign and original candidate width/sign plus warning. It applies only to unverified non-ID integer columns whose physical value width exceeds the candidate hint. All values in that column remain exact; inferred references are suppressed. Verified named fields retain strict validation. Reader revision `wdc5-values-v7` and distinct full/projection admission revisions fence retained artifacts. Older supported admission evidence remains readable so preparation can refresh a stale interpretation without deleting retained source bytes.

Optional `textIssues` on a row identifies unavailable text by flattened zero-based column index, closed code `DB2_TEXT_ENCODING_INVALID`, and exact lowercase pre-NUL `rawBytesHex`. Such a cell has an internal empty placeholder, which must never be presented as valid empty text. The affected column must be a non-ID string; duplicate/unsorted indices, valid UTF-8 falsely called invalid, embedded NUL, or more than 65,535 aggregate raw bytes per row are rejected. The table permits at most 16 MiB emitted raw evidence, including copies. Optional snapshot `textIssueCount` counts affected emitted cells, including copies; omitted legacy counts mean zero. Other cells remain usable. The default pure reader stays strict; table admission explicitly enables this preservation policy.

A full source receipt uses `content-blte-v1` and null projection; partial receipts use `content-blte-projection-v1` and a canonical source-bound `blte-clear-chunks-v1` partition. The internal artifact decoded digest is the full decoded SHA for full sources and the canonical projection identity for partial ones. Receipt and admission policy discriminate them; they cannot substitute for each other. Containers with more than 128 BLTE chunks coalesce adjacent readable chunks into authenticated spans; holes retain original chunk ordinals through 65,535. The combined readable/unavailable range budget remains 128. Smaller containers preserve their original per-chunk evidence identities.

Initial budgets:256MiB decoded source, one million rows,512 flattened columns,64KiB string values,256KiB serialized public row,512KiB complete public row page,512MiB immutable artifact, at most256 eligible ROOT receipts. Final DTO null fields and quoted IDs count toward response budgets. A shortened page resumes at its first unreturned row; no record is skipped to fit a page. Archive discovery uses4 workers and bounded time/metadata bytes. No game content is included in source or test fixtures.

The v6 reader supports the reviewed finite inline/external scalar relationship profiles, section-local ordinal or secondary physical-ID keys, terminal-origin copies and bounded exact relationship blocks. Unverified inline accelerators are explicitly unsupported. Historical v5 admissions remain readable for source-preserving refresh; new rows require the current revision. Relationship metadata does not establish global uniqueness in a partial target.

The production adapter now uses full/partial `table-admission-v2` / `table-admission-projection-v2` profiles. Its only verified-name raw-width override is the reviewed pinned ItemSubClass definition SHA, actual95D8638F/1E67DB87 layout, ordinal6 PrerequisiteProficiency, Pallet32 versus signed8 candidate. The pure reader accepts at most8 snapshotted exact rules and defaults to strict interpretation. It matches verified definition digest, table/layout, selected field ordinal/name, storage kind and physical/candidate widths/sign before Header. Wrong contexts stay strict; IDs/relationships cannot opt in. All rows in that one column retain raw physical32 evidence with a warning and no inferred reference or calculated semantics. Historical v3–v6 partial admissions remain readable for source-preserving refresh; unknown/unreleased interpretations do not gain authority.

Adapter-v3 adds exactly three reviewed CreatureDisplayInfo research-only width rules under the pinned64f98132... definition and BFDAF9F1/7275F5F6: NPCSoundID ordinal8/Pallet32, ObjectEffectPackageID ordinal12/Common32, AnimReplacementSetID ordinal13/Common32, each versus unsigned16. Model/texture/ID fields stay strict. The known v7/admission-projection-v2 interpretation remains readable for source-preserving refresh, while new commits require v3. See the [WoW data reference](../docs/WOW-DATA-REFERENCE.md#data-quirks) for every raw-evidence field.

ItemEffect `Charges`, `SpellCategoryID` and `ChrSpecializationID` are raw evidence only (whole physical uint32, candidate 16-bit width kept as a warning). They are never semantic values or join keys.
